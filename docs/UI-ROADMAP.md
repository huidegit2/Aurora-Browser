# 界面与功能优化路线

> 这是基于现有源码的建议，不代表这些改动已经实现，也不替代真机可用性测试。优先解决首次连接、失败恢复与触屏可达性，再做增强功能。

跨平台手工验收步骤见[实机验证清单](DEVICE-VALIDATION.md)；清单中的项目需在对应真实设备上逐项记录，自动化测试不能代替这些验证。

## P1：优先改善

### 1. 首次 HTTPS 与证书引导

**现状：** HTTPS 入口、CA 下载和连接自检集中在设置弹窗的 HTTPS 区域；若用户因入口证书错误而无法进入页面，页内说明本身不可达。安装包介绍已有独立证书说明，可作为入口级引导的外部补充。

**建议：** 首次访问或者自检确认不安全上下文时，展示一张简短、可关闭的指引卡：推荐入口、内置 CA 与域名证书两种路径、按设备下载证书的按钮，以及“连接自检”入口。已完成信任后不要每次重复打断。

**验收：** 首次打开能区分 HTTP 与 HTTPS；证书失败时能找到下一步；成功后可重跑自检；不会将信任证书操作误表述为自动完成。

### 2. 在网页视口内显示错误与恢复

**现状：** 代理帧错误和加载超时会停止加载状态并写入状态栏；窄屏 CSS 会隐藏状态栏文字，用户可能只看到空白内容。实现位于[前端页面](../app/www/index.html)的 `watchTabFrame`、导航超时处理及 `.status-text` 响应式样式。

**建议：** 在当前标签页内容区渲染轻量错误卡片，给出简短原因和“重试”“返回”“连接自检”操作。保留原有地址与历史，不要把任意站点返回的错误 HTML 当作可信管理 UI 注入。

**验收：** 模拟代理帧 error、超时和自检不可达时，桌面与手机都能看到提示；重试沿用当前 URL；恢复后清除旧提示；旧标签的迟到错误不得覆盖新导航。

### 3. 窄屏工具栏与触控可达性

**现状：** 窄屏规则会隐藏主页、主题与状态文字；通用 `.nav-btn` 为 32×32 CSS 像素，地址栏可能被左右控件挤压。尚未有真机触控测量。

**建议：** 根据使用频率重新安排空间：地址输入与前进/后退优先，主题、主页等低频项放入菜单；适当增加关键触控目标，确保地址栏有合理最小宽度、弹窗按钮不被遮挡。不要只凭桌面缩放模拟断言移动端已改善。

**验收：** 在窄屏竖屏和横屏下无需精确点按；常用导航、地址栏、设置与弹窗都可见可达；软键盘弹出后内容仍可滚动。

## P2：体验增强

### 4. 标签页语义、键盘与触屏切换

**现状：** 标签项由动态 `div` 承载，主要依赖点击、桌面拖动和右键菜单；键盘快捷键已支持 Ctrl+Tab、Ctrl+数字和关闭／恢复。

**建议：** 为标签栏增加 tablist/tab 与选中状态语义、稳定焦点样式和方向键切换；增加显式标签总览入口，触屏无需依赖拖拽或右键菜单。保留现有快捷键。

**验收：** 键盘可以聚焦、切换、关闭并恢复标签；屏幕阅读器能读出标签名称和当前选中状态；触屏能从总览切换到指定标签。

### 5. 书签和历史管理

**现状：** 书签可添加、打开、删除；历史可打开与清空，地址栏能匹配书签和近期历史。

**建议：** 优先给书签增加编辑名称、网址和分类的操作，再考虑历史搜索、日期分组与逐项删除。清空历史等不可逆操作应加确认或短时撤销。

**验收：** 修改书签后新标签页、快捷栏和地址栏建议同步刷新；历史搜索不泄漏到目标网站；空状态写清楚如何添加或恢复内容。

### 6. 设置状态反馈和易读性

**现状：** 搜索引擎、主题、密码与证书域名分别写入设置；不同操作的失败提示不完全统一。

**建议：** 给每个设置补充“正在保存／已保存／失败并保留原值”的状态；密码设置区说明当前受 UI 配置还是 `AUTH_TOKEN` 环境变量锁定；用键盘焦点、对比度和 `prefers-reduced-motion` 做一次集中检查。

**验收：** 网络断开或 API 返回错误时，不显示虚假的成功状态；环境变量锁定清楚可见；键盘焦点可识别且动画可降低。

## 推荐顺序

1. 先用实际用户操作记录复现入口、白屏和窄屏问题，确认现有自检能否定位原因。
2. 实现视口错误恢复卡与首次 HTTPS 引导；补回归测试覆盖迟到回调、重试和手机布局。
3. 做真机窄屏与触控检查后再调整工具栏尺寸。
4. 最后迭代标签无障碍、书签历史管理和设置反馈。

不建议在没有复现与验收标准前重做整套视觉风格。核心代理可靠性和错误恢复优先于增加动画或堆叠新功能。
