# 连接、证书与常见问题

[返回首页](../README.md) · [开发与发布](DEVELOPMENT.md) · [验证范围](../IMPLEMENTATION-NOTES.md)

本指南区分应用入口、界面初始化与目标网站访问的问题。下文的 `192.168.1.10` 是示例 NAS IP，请替换为实际地址；更改过端口时，也要替换对应端口。

## 安装后在哪里查看证书说明

在 fnOS 应用中心打开“极光浏览器”的应用详情，查看应用介绍。新版安装包的介绍包含证书下载地址、Windows / Android / iPhone 的信任步骤和完整指南地址，无需先进入 Aurora 页面。

应用中心的安装包介绍来自 [manifest](../manifest) 的 `desc`；FnDepot 应用源中的介绍来自 [fnpack.json](../fnpack.json) 的应用描述。这两处均提供证书摘要，详细步骤以本指南为准。

安装包介绍随 FPK 安装或升级更新。只更新 GitHub 文档或刷新 FnDepot 索引，不会重写 NAS 上旧安装包的介绍；不同 fnOS 版本的详情入口与排版也可能不同。

## 先确认问题出现在哪一层

| 现象 | 优先检查 |
| --- | --- |
| 还没看到工具栏，浏览器已提示证书或连接错误 | 应用运行状态、地址与端口、入口证书 |
| 可以看到工具栏，但主页空白或一直加载 | 认证、接口错误、客户端存储与初始化提示 |
| 主页正常，只有打开的网站空白 | 代理模式、目标站点、WebSocket 与网站兼容性 |
| 系统浏览器正常，飞牛 App 内仍打不开 | App 内置页面的证书信任、Service Worker 和页面承载方式 |

记录错误提示、应用版本、访问入口和客户端版本，有助于区分这些问题。

## 主页能否到达

在与 NAS 同一可信局域网内，用系统浏览器检查：

```text
http://192.168.1.10:18920
https://192.168.1.10:18921
```

- HTTP `18920` 可用于区分服务不可达和 HTTPS 入口问题。
- HTTPS `18921` 需要证书受信任，并且证书覆盖当前访问的 IP 或域名。
- 局域网 IP 的普通 HTTP 页面不满足完整代理所需的安全上下文；打开主页不代表 Scramjet 已启用。
- 未经认证时，业务接口可能拒绝访问，这不等于服务没有启动。

若两种入口都无法连接，先检查应用运行状态、网络、防火墙和端口。不要为了排障把没有访问保护的代理服务直接开放到公网。

## 入口证书不受信任

可以选择有效域名证书，或在每台访问设备上信任 Aurora 自带的本地根 CA。已有受信任域名证书时，通常无需再安装 Aurora 的本地 CA。

### 使用内置本地根 CA

#### 第一步：获取自己 NAS 的证书

应用使用内置证书模式时，首次启动会生成本地 CA。打开 Aurora 后，可从“HTTPS 全功能”证书入口下载；如果 HTTPS 页面尚无法进入，在自己的可信局域网内直接用系统浏览器下载：

| 访问设备 | 下载地址 |
| --- | --- |
| Windows、Android、macOS | `http://192.168.1.10:18920/aurora-ca.crt` |
| iPhone、iPad，使用 Safari | `http://192.168.1.10:18920/aurora-ca.mobileconfig` |

这两个下载接口不要求先打开 Aurora 界面或登录。HTTP 下载只用于可信局域网内的首次配置；核对 NAS 地址和证书来源后再导入。也可由管理员通过可信通道传递证书。

HTTPS 已可信时，以下路径同样可下载：

```text
https://192.168.1.10:18921/aurora-ca.crt
https://192.168.1.10:18921/aurora-ca.mobileconfig
```

只需下载公开 CA 证书或描述文件，不要导出或分享 CA 私钥、服务器私钥。

#### 第二步：在访问设备上安装并信任

**Windows（Chrome / Edge）**

1. 打开下载的 CA 证书，选择“安装证书”。
2. 选择“当前用户”，然后选择“将所有的证书都放入下列存储”。
3. 浏览并选择“受信任的根证书颁发机构”，确认导入自己的 NAS CA。
4. 关闭并重新打开浏览器，再访问 HTTPS 入口。由管理员统一配置时，也可按组织策略导入本地计算机的对应存储。

**Android**

1. 在系统设置中搜索“安装证书”，进入安全、加密与凭据等相关页面。
2. 选择安装“CA 证书”，选取下载的 CA 文件并按系统提示确认。不同厂商的菜单名称可能不同。
3. 重新打开系统浏览器访问 HTTPS 入口。

用户安装的 CA 不一定被所有 App 或 WebView 采用。飞牛 App 内仍报错时，先用同一手机的系统浏览器对照；不能仅凭证书已安装就认定所有 App 都会信任。

**iPhone / iPad**

1. 使用 Safari 下载描述文件，并允许下载。
2. 打开“设置 → 通用 → VPN 与设备管理”，选择 Aurora CA 描述文件并完成安装；也可从“已下载描述文件”入口进入。
3. 再打开“设置 → 通用 → 关于本机 → 证书信任设置”，为该根证书开启完全信任。
4. 返回 Safari，重新打开 HTTPS 入口。受管理设备的安装权限与信任策略可能由管理员控制。

安装描述文件后仍需完成第 3 步。单纯下载或安装描述文件，不代表手工安装的根证书已经获得完全信任。

**macOS 与 Firefox**

macOS 可用“钥匙串访问”导入 CA，在证书的“信任”设置中信任该 CA。Firefox 的证书来源受版本与策略影响；若系统已信任而 Firefox 仍报警，检查其“隐私与安全 → 证书 → 查看证书 → 证书颁发机构”，必要时单独导入并信任用于识别网站的 CA。

#### 第三步：确认完整代理条件

重新打开：

```text
https://192.168.1.10:18921
```

确认没有证书错误，再打开 Aurora 的“连接自检”，检查安全上下文、Service Worker 和 Wisp 通道。仅点击“继续访问”跳过警告，不能保证 Service Worker 可用；成功信任 CA 也不代表任意网站都能正常代理。

同一 CA 通常无需反复安装，但每台访问设备需要分别配置。重装、清空数据或更换 NAS 后，CA 可能变化，届时需核对并更新信任。IP 或域名变化后仍提示名称不匹配时，应检查实际入口、附加证书域名设置，并重启应用更新内置服务器证书。

### 使用已有域名证书

可选择以下方式：

- **HTTPS 反向代理**：将独立域名的根路径代理到 NAS 本机的 `http://127.0.0.1:18920`，启用 WebSocket 转发。反代运行在其他主机时，应将上游改为它能访问的 NAS 地址。
- **应用直接加载证书**：将完整证书链和私钥放入应用数据目录的自定义证书位置，或设置环境变量后重启应用。

默认自定义证书位置与可覆盖变量：

```text
DATA_DIR/tls/custom.crt.pem
DATA_DIR/tls/custom.key.pem
TLS_CERT_PATH
TLS_KEY_PATH
```

`DATA_DIR` 表示实际应用数据目录，不能原样作为目录名使用。证书链和私钥需配对且可由应用读取；访问时使用证书覆盖的域名。直接配置证书后仍使用 HTTPS `18921`，证书续期后的文件替换与应用重启由管理员安排，应用不会自动向证书机构申请或续期。

当前代码存在根路径资源和 Service Worker 路径假设。建议使用独立域名根路径，不要直接假定挂到任意子路径或 fnOS 统一网关后即可使用。

### 反向代理应保留什么

- 客户端访问时的 `Host`，包括非默认端口。
- 正确的 `X-Forwarded-Proto`。
- WebSocket 升级与长连接转发。

管理 API 与 Wisp 会检查浏览器来源。反代后返回 `403` 或来源不可信时，先核对上述信息；不要关闭来源校验，也不要用任意 `X-Forwarded-Host` 冒充真实入口。

### 访问局域网目标

为避免代理被用来访问 NAS 内部服务、回环地址或 DNS 指向内网的域名，内网目标代理默认关闭。轻量代理会检查 DNS 返回的全部地址，并固定实际连接地址，阻止检查后解析结果被替换；Wisp 同样默认拒绝私有地址。

仅在可信网络且确实需要访问路由器、PVE 等设备时，才在 Aurora 服务启动环境设置：

```text
ALLOW_PRIVATE_NETWORK_PROXY=1
```

重启应用后生效。该开关会允许代理访问 NAS 可达的内网目标；如果服务对公网开放，不要启用。没有启用时，局域网目标会在 Aurora 中明确显示为已阻止，普通互联网网站不受影响。

### 电脑上的临时本地入口

已有 NAS SSH 访问权限时，可建立只转发到本机的隧道：

```sh
ssh -N -L 18920:127.0.0.1:18920 用户名@NAS地址
```

随后在这台电脑的浏览器中打开：

```text
http://localhost:18920
```

浏览器对本机回环地址有安全上下文例外。它仍要求 SSH 隧道和其他代理依赖正常，不能代替手机或飞牛 App 的证书配置。

## 目标网站的 HTTPS 证书报错

先确认错误发生在“Aurora 入口”，还是“NAS 连接的目标网站”。这两条连接的信任配置互不替代。

从 v1.0.24 起，基础代理使用 Node 默认 TLS 校验。访问自签名 HTTPS 路由器、PVE 或其他设备时，应修正目标证书，或由管理员在 Aurora 进程启动前配置受信 CA：

```sh
NODE_EXTRA_CA_CERTS=/实际路径/受信CA.pem
```

这是启动环境变量的示意，需要通过实际服务启动配置传入，重启后生效。它不会自动修改手机或电脑对 Aurora 入口的信任，也不代表 Scramjet/Wisp 的所有目标连接均由这项配置控制。不要把全局忽略 TLS 校验作为默认修复方式。

## 手机或飞牛 App 显示白屏

按以下顺序对照：

1. 区分整个应用界面空白，还是只有目标网站内容空白。
2. 用同一手机的系统浏览器打开相同 HTTPS 入口，核对证书和认证提示。
3. 主页可见时，打开“连接自检”，检查安全上下文、Service Worker 和 Wisp 通道。
4. 仅某个网站失败时，记录目标网站、代理模式和具体操作。
5. 仅飞牛 App 内失败时，补充 App 版本与系统浏览器的对照结果。

v1.0.24 改善了初始化容错、请求超时和错误提示；手机白屏的现场根因尚未完整复现，当前不能声称所有手机或 WebView 兼容性问题已经修复。

## 升级后找不到 NAS 下载

v1.0.26 起已移除 NAS 下载管理、目录选择器、任务和文件管理接口，设置中也不再提供下载目录选项。这是功能收敛，不是权限丢失或界面加载失败。

- 应用不会继续执行旧版下载任务，也不会主动修改或删除旧版的下载文件与记录。
- 需要取回旧文件时，使用 fnOS 文件管理器打开原保存目录。默认位置是实际应用数据目录下的 `downloads/`；曾选用共享文件夹时，以原设置为准。
- 网页下载链接交给当前设备的浏览器处理，实际结果仍取决于网站、代理模式和客户端策略；不承诺所有站点可用。
- HTTPS 根证书下载不受此次移除影响，首次连接继续按本文的证书步骤配置。

## 反馈问题时提供什么

- Aurora 版本、NAS 系统版本及 CPU 架构。
- 客户端系统、浏览器或飞牛 App 版本。
- 入口使用 HTTP/HTTPS、IP/域名，是否经过反向代理。
- 白屏出现的位置、连接自检结果与可复现的操作步骤。
- 相关错误码或脱敏日志。

提交前删除访问口令、Cookie、带认证参数的完整网址、私钥与私人文件路径。需要提供目标网站时，优先使用不含个人登录信息的公开页面。
