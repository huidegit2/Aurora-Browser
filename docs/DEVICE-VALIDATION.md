# Aurora-Browser 实机验证清单

本清单用于发布前在真实设备上记录入口证书、代理浏览和窄屏操作表现。以下项目目前均为**待实测**；桌面自动化测试通过不代表手机或 fnOS 内置页面已通过。

## 测试记录

每轮测试记录 Aurora 版本、fnOS 版本、设备型号、浏览器名称与版本、访问方式（局域网地址或反向代理域名）及日期。不要把密码、访问令牌、Cookie 或带凭据的网址写入记录。

## fnOS 内置应用页面

- [ ] 从 fnOS 应用入口打开 Aurora；页面布局完整，入口证书状态符合预期。
- [ ] 查看“连接自检”，记录安全上下文、Service Worker、HTTPS 和 WebSocket 结果；确认失败时的提示可读。
- [ ] 打开普通链接、新窗口链接和下载链接，确认导航留在预期标签页，下载交由客户端处理。
- [ ] 在窄窗口和横向窗口中检查地址栏、导航按钮、设置弹窗和自检弹窗是否被挤压或遮挡。

## iPhone / iPad Safari

- [ ] 使用受信任的域名证书，或按[证书与排障指南](TROUBLESHOOTING.md#使用内置本地根-ca)安装配置文件并在系统证书信任设置中启用完全信任；重新打开 HTTPS 入口。
- [ ] 在 Safari 中查看连接自检，确认 HTTPS 页面和 Service Worker 状态；测试首页、普通网页及前进 / 后退。
- [ ] 测试页面内普通链接、新窗口链接、返回 Aurora 和外部下载链接，记录系统对下载文件的处理方式。
- [ ] 聚焦地址栏并弹出软键盘；检查键盘出现时页面、弹窗和主要按钮仍可滚动、可操作。
- [ ] 分别检查竖屏和横屏下的工具栏、标签页、菜单和自检弹窗。

## Android 浏览器

- [ ] 使用受信任的域名证书，或按[证书与排障指南](TROUBLESHOOTING.md#使用内置本地根-ca)安装 CA；确认当前浏览器和系统版本实际信任该证书。
- [ ] 在实际使用的 Android 浏览器中查看连接自检，确认 HTTPS 页面和 Service Worker 状态；测试首页、普通网页及前进 / 后退。
- [ ] 测试页面内普通链接、新窗口链接、返回 Aurora 和外部下载链接，确认下载通知或下载管理器行为符合预期。
- [ ] 聚焦地址栏并弹出软键盘；检查页面滚动、弹窗按钮和地址栏操作。
- [ ] 分别检查竖屏和横屏下的工具栏、标签页、菜单和自检弹窗。

## 结果记录

每项填入“通过 / 失败 / 不适用”，失败时附上复现步骤、脱敏后的自检摘要和客户端版本。遇到证书错误时先记录具体设备与浏览器行为，不要将忽略警告当作通过；更换设备、系统或浏览器大版本后应重新验证相关项目。
